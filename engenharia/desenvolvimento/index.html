    Executar localmente¶

    Pré-requisitos¶

    • Node.js e npm compatíveis com Next.js 15.
    • PostgreSQL (o projeto de produção usa Supabase/Postgres) para login, painel, bots e persistência.
    • Chaves dos provedores/canais apenas se for testar inferência real.

    O ensaio local da landing pode ser aberto sem configurar provedores. As páginas/API que consultam banco precisam de DATABASE_URL válido.

    Instalar e iniciar¶

    npm install
Copy-Item .env.example .env.local
# Edite .env.local e configure DATABASE_URL, chave de cifragem e provedores necessários.
npm run dev

    Não use uma connection string de produção em computador compartilhado. Use um banco de desenvolvimento e nunca cole os segredos em issue, chat ou commit.

    Verificação antes de enviar mudança¶

    npm test
npm run build
git diff --check

    Os testes são em tests/*.test.mjs. Eles cobrem contratos de autorização, deduplicação, RLS e comportamentos de produto; não substituem um smoke test autenticado com banco configurado.

    Migração manual, quando necessária:

    npm run db:migrate

    As atualizações do schema são idempotentes. Revise lib/db/schema.sql, lib/db/cliente.ts e o script antes de rodar contra produção.

    Prévia local da documentação¶

    python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-docs.txt
mkdocs serve

    Para validar como no CI: mkdocs build --strict --config-file mkdocs.yml. O diretório site/ é saída gerada; não edite HTML compilado à mão.

    Publicação do manual¶

    O código do TARS é mantido em repositório privado e o GitHub Pages gratuito requer um repositório público. Por isso, o workflow compila somente docs/ e publica o HTML num repositório público separado; o código-fonte da aplicação não é copiado.

    Para habilitar a publicação automática no GitHub:

    1. Crie um repositório público vazio para o site (por exemplo, tars-docs) e habilite GitHub Pages usando a branch gh-pages.
    2. Crie uma chave SSH Ed25519 de deploy e cadastre a chave pública nesse repositório com permissão de escrita.
    3. Cadastre a chave privada no repositório privado do TARS em Settings → Secrets and variables → Actions, como TARS_DOCS_DEPLOY_KEY.
    4. Cadastre TARS_DOCS_REPOSITORY como variável do repositório, com o caminho dono/repositorio do site público. Se conhecido, defina também TARS_DOCS_URL com a URL pública final.
    5. Rode Actions → documentacao → Run workflow ou envie alterações de documentação para main.

    O workflow falha antes de publicar se a geração estrita detectar links quebrados ou se o site compilado contiver extensão de código. O repositório público de saída recebe apenas o artefato MkDocs e é espelhado no branch gh-pages.
