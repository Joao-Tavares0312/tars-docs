    Zendesk¶

    O painel conecta a Zendesk por instância em Configurações → Zendesk. Duas coisas independentes, ligadas ou desligadas separadamente:

    1. Ticket no handoff — quando o bot encaminha a conversa pra humano (pedido explícito, regra de handoff ou falha de inferência), um ticket é criado na Zendesk com o resumo do que aconteceu.
    2. Sincronização do Help Center — puxa os artigos publicados do Help Center e vira base de conhecimento do bot, um documento por artigo.

    Custo¶

    A Zendesk não tem plano gratuito — só um trial de 14 dias, e depois disso o mínimo é o plano Support Team pago. O TARS não consegue verificar plano nem cobrança de nenhuma credencial externa; confira isso antes de conectar.

    Credencial¶

    Gere um API Token em Admin Center → Apps and integrations → APIs → Zendesk API (é preciso um admin habilitar o acesso por token primeiro). A credencial é validada contra GET /api/v2/users/me.json antes de salvar — token inválido não vira integração "conectada" que não funciona.

    Cifrada com TARS_ENCRYPTION_KEY, igual toda outra credencial do projeto; a tela só mostra uma versão mascarada depois de salva.

    Ticket no handoff¶

    Best-effort, fora do caminho crítico da resposta ao usuário: se a Zendesk falhar ou estiver fora do ar, o atendimento já existe na Fila humana do próprio TARS — a pessoa não fica sem fila só porque o espelho externo engasgou. O id do ticket criado fica salvo no atendimento (atendimentos.zendesk_ticket_id).

    Limitação conhecida: handoff disparado por feedback negativo (👎 numa resposta) não cria ticket na Zendesk — só os dois handoffs de conversa em andamento (pedido explícito e falha de inferência) criam. lib/db/feedback.ts é um módulo de banco sem rede, igual usuarios.ts não manda e-mail sozinho.

    Sincronização do Help Center¶

    Exige o campo "Habilitar sincronização do Help Center" marcado — estar conectado não é suficiente, é um opt-in separado. Ao sincronizar:

    • Busca todos os artigos publicados (rascunhos são ignorados) via GET /api/v2/help_center/{locale}/articles.json, paginado.
    • Cada artigo vira um documento de conhecimento em rascunho — publicar continua exigindo o clique em "Validar e publicar" em Conhecimento, igual qualquer outra fonte.
    • Rodar de novo atualiza os artigos já importados em vez de duplicar (upsert por id do artigo na Zendesk, documentos_conhecimento.origem_zendesk_id).
    • Artigos com menos de 20 caracteres de texto depois de tirar o HTML são ignorados (nada pra indexar).

    Limites da primeira versão¶

    • Locale fixo em pt-br. Help Center multilíngue com conteúdo relevante só em outro idioma precisa de ajuste manual no código.
    • Sincronização é sob demanda (botão no painel), não agendada.
    • Só cria ticket; não lê, atualiza nem fecha tickets existentes.
