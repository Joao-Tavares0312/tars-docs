    Ferramentas externas (somente leitura)¶

    O painel permite cadastrar até três consultas externas por assistente em Configurações → Ferramentas API. O ciclo é opcional: sem ferramenta ativa, a mensagem usa o fluxo normal de inferência.

    Limites da primeira versão¶

    • Só aceita endpoint HTTPS público na porta padrão; endereços locais, IPs literais, DNS que resolve para rede privada, redirects, credenciais na URL e query strings fixas são bloqueados.
    • A ação é sempre GET. O TARS não cria, altera ou apaga dados em sistemas externos.
    • Cada ferramenta declara no máximo oito argumentos (string, integer, number ou boolean). O modelo só consegue preencher esses argumentos, que são codificados como parâmetros de query.
    • Cada mensagem executa no máximo uma ferramenta; o ciclo faz uma chamada ao modelo para escolher a ferramenta e outra para redigir a resposta. A função exige o adaptador Groq.
    • A resposta externa tem limite de 64 KB na conexão e é reduzida a 8.000 caracteres antes de ser enviada ao modelo. A auditoria registra ferramenta, canal, status, latência e erro curto por até 90 dias; não persiste argumentos, resposta ou segredo.
    • Credenciais são cifradas com TARS_ENCRYPTION_KEY, nunca retornadas à interface. O cabeçalho permitido é X-API-Key ou Authorization.

    Configuração de argumentos¶

    Informe o endpoint sem query string. Exemplo para uma API de estoque:

    https://api.exemplo.com/v1/estoque

    E declare os argumentos que o modelo poderá consultar:

    [
  {
    "nome": "sku",
    "descricao": "Código exato do produto",
    "tipo": "string",
    "obrigatorio": true
  }
]

    O TARS validará os nomes e tipos novamente antes de chamar a API. O valor de sku é acrescentado com URLSearchParams; não pode mudar host, método ou cabeçalhos.

    Fluxo de execução¶

    Telegram/Webchat
  → regras, autorização do canal e cotas
  → modelo escolhe uma ferramenta e emite argumentos
  → validação de argumentos e endpoint
  → requisição HTTPS GET com timeout, limites e sem redirect
  → resposta truncada e marcada como dado externo não confiável
  → modelo formula a resposta final
  → trilha operacional sem conteúdo sensível

    O TARS não adiciona uma assinatura por habilitar a função, mas não consegue verificar o plano, saldo, cotas ou cobrança vinculados à chave Groq nem ao serviço consultado. O ciclo pode fazer uma inferência adicional e a API externa pode cobrar. Verifique as contas e limites antes de ativar; não há garantia de custo zero por parte do TARS. A resposta do endpoint é enviada ao Groq para gerar a resposta e deve ser adequada para processamento pelo modelo.

    API administrativa¶

    GET /api/ferramentas?instancia_id=... lista configurações sem segredos. POST /api/ferramentas cria ou atualiza uma configuração e DELETE /api/ferramentas remove; todas exigem sessão e permissão de edição na instância. GET /api/ferramentas/execucoes?instancia_id=... lista o histórico resumido.

    As tabelas ferramentas_api e ferramentas_api_execucoes têm RLS habilitada e privilégios revogados para os papéis anon e authenticated; a aplicação valida a permissão da equipe antes de ler ou alterar os dados.

    Fora de escopo por enquanto¶

    Chamadas de escrita, webhooks de saída e ações como criar tickets permanecem desativadas. Elas exigem confirmação explícita por conversa, prevenção de duplicidade, recuperação após timeout e revisão de permissões antes de serem habilitadas.
