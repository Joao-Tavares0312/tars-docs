    Primitivas de controle — plano de implementação¶

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Dar ao TARS uma primitiva única de campo, botão e aba — declarada no elemento nativo, não por escopo de componente — e com ela corrigir os inputs crus do painel, o texto colado na borda dos botões e o desalinhamento das duas seções da landing page.

    Architecture: Um bloco novo de regras de elemento em app/globals.css, logo após o font: inherit da linha 74. Campo entra na camada 0 (opaco, cantos vivos), botão na camada 2 (vidro + --raio-sm), aba em nenhuma das duas (mono maiúsculo com régua âmbar embaixo). A .linha-acao — que hoje é ação inline e botão preenchido ao mesmo tempo — se parte em .acao-inline e .acionador. As ~20 declarações ad-hoc de aparência de controle são removidas dos escopos de componente, que passam a herdar. Quatro exceções ficam nomeadas por seletor. A navegação por teclado das abas sai como função pura em lib/abas.mjs, consumida por um componente <Abas>.

    Tech Stack: Next.js 15, React 19, TypeScript 5.6, CSS puro (sem framework), node --test com node:assert/strict.

    Global Constraints¶

    • Spec de origem: docs/superpowers/specs/2026-09-24-primitivas-de-controle-design.md. Em caso de divergência entre este plano e a spec, a spec vence.
    • Regra das três camadas (DESIGN.md): camada 0 = a folha (opaca, cantos vivos, régua de 1px, sem backdrop-filter); camada 1 = o que paira; camada 2 = o que aciona (vidro + --raio-sm).
    • Nenhum literal de blur ou raio fora dos tokens --vidro-blur, --raio, --raio-sm. A suíte quebra.
    • Nenhum !important em border-radius, backdrop-filter, background, background-color, color ou border-color dentro de bloco de vidro. A suíte quebra.
    • Piso da mono: 11px, direto ou por herança na cascata.
    • Estado desabilitado nunca usa opacity — fundo transparente, borda var(--regua), texto var(--tinta-fraca).
    • Estado nunca é comunicado só por cor — sempre texto, borda ou posição junto.
    • A variável mono é --fonte-mono, nunca --mono (que nunca existiu e invalida o shorthand font: inteiro).
    • Comandos: testes com npm test; typecheck com npx tsc --noEmit; build com npm run build.
    • A suíte existente (87 testes) precisa continuar verde em toda task.
    • Commits em português, no padrão do repositório (fix:, feat:, test:, docs:, refactor:).

/** Alvo: qualquer regra que pinte um controle. */
const ALVO_CONTROLE = /(^|[\s>+~])(input|select|textarea|button)\b|\.(campo|campo-inline|acionador)\b/;
const PROP_DE_APARENCIA = /^\s*(background|background-color|border|border-color|color)\s*$/;

test("aparência de controle vem de token, nunca de hex literal", async () => {
  const problemas = [];
  for (const arq of CSS) {
    for (const { seletores, corpo } of extrairRegras(semComentarios(await ler(arq)))) {
      if (!seletores.some(s => ALVO_CONTROLE.test(s))) continue;
      if (seletores.some(s => EXCECOES_DE_CONTROLE.includes(s))) continue;
      for (const d of corpo.split(";")) {
        const i = d.indexOf(":");
        if (i === -1) continue;
        const prop = d.slice(0, i), valor = d.slice(i + 1);
        if (PROP_DE_APARENCIA.test(prop) && /#[0-9a-f]{3,8}\b/i.test(valor))
          problemas.push(`${arq}: ${seletores.join(",")} { ${d.trim()} }`);
      }
    }
  }
  assert.deepEqual(problemas, [], `hex literal em controle (use token):\n${problemas.join("\n")}`);
});

/**
 * A lista fechada de exceções vive DENTRO da asserção de propósito: exceção
 * nova só passa sendo acrescentada ali, o que força a decisão a ser escrita em
 * vez de aparecer como um padding solto num escopo qualquer.
 */
test("padding de controle vem do token, fora as exceções nomeadas", async () => {
  const problemas = [];
  for (const arq of CSS) {
    for (const { seletores, corpo } of extrairRegras(semComentarios(await ler(arq)))) {
      if (!seletores.some(s => ALVO_CONTROLE.test(s))) continue;
      if (seletores.some(s => EXCECOES_DE_CONTROLE.includes(s))) continue;
      const pad = corpo.match(/(?:^|;)\s*padding\s*:\s*([^;]+)/);
      if (pad && !/var\(--controle-pad-[xy]\)/.test(pad[1]))
        problemas.push(`${arq}: ${seletores.join(",")} -> padding:${pad[1].trim()}`);
    }
  }
  assert.deepEqual(problemas, [], `padding de controle fora do token:\n${problemas.join("\n")}`);
});

    /**
 * Navegação de tablist por teclado, no padrão WAI-ARIA.
 *

 * `node --test tests/*.test.mjs`, sem transpilação, e `allowJs` já está ligado

 * build do Next, sem flag experimental e sem dependência nova.
 *
 * @param {string} tecla  `event.key`
 * @param {number} atual  índice da aba ativa
 * @param {number} total  quantidade de abas
 * @returns {number|null} novo índice, ou null se a tecla não navega — nesse
 *   caso o componente NÃO deve chamar preventDefault, senão engole Enter,
 *   espaço e Tab.
 */
export function proximoIndiceDeAba(tecla, atual, total) {
  if (total <= 0) return null;
  switch (tecla) {
    case "ArrowRight": return (atual + 1) % total;
    case "ArrowLeft": return (atual - 1 + total) % total;
    case "Home": return 0;
    case "End": return total - 1;
    default: return null;
  }
}

export default function Abas({
  itens, ativo, aoTrocar, rotulo, className,
}: {
  itens: readonly ItemDeAba[];
  ativo: string;
  aoTrocar: (id: string) => void;
  rotulo: string;
  className?: string;

    refs.current[proximo]?.focus();

          key={item.id}
          ref={el => { refs.current[i] = el; }}

          role="tab"
          id={`aba-${item.id}`}
          aria-selected={item.id === ativo}

          className={item.classe}
          onClick={() => aoTrocar(item.id)}
        >
          {item.rotulo}
        </button>
      ))}
    </div>
  );

    ### A primitiva de controle

Campo e botão têm **uma** altura e **um** padding, declarados no elemento
nativo — não por escopo de componente.

| Token | Valor | Papel |
|---|---|---|
| `--controle-alt` | `40px` | `min-height` de todo controle de bloco |
| `--controle-pad-x` | `var(--e3)` | padding horizontal |
| `--controle-pad-y` | `10px` | padding vertical |

A regra é de **elemento** (`input, select, textarea` e `button`), e a razão é a
garantia: um componente estiliza o controle que alguém lembrou de classificar;
o elemento estiliza também o que alguém esqueceu. O estado anterior tinha vinte
escopos `.componente input` e nenhuma base, então campo sem classe caía no
agente de usuário — era daí o HTML cru no painel, e cinco paddings diferentes
(8, 9, 11, 12, 13px) desalinhando botões vizinhos.

Camada, sem exceção nova: **campo é camada 0** (é onde o dado mora, não um
gatilho), **botão é camada 2**, **aba não é nenhuma das duas** — mono maiúsculo
com régua embaixo, como a seção *As duas folhas* já dizia.

**`.linha-acao` não existe mais.** Ela era ação de texto sublinhada
(`padding: 0 0 1px`, correto para inline) e botão preenchido de vidro ao mesmo
tempo, e o segundo papel chegou por acidente de cascata. Virou `.acao-inline`
(o sublinhado dentro da linha de especificação) e `.acionador` (o botão).

**As quatro exceções, nomeadas por seletor** — exceção que não está escrita
vira `!important` na revisão seguinte:

| Exceção | Por quê |
|---|---|
| `input[type=checkbox]`, `input[type=radio]` | 40px e fundo de campo dariam um retângulo com um pontinho dentro |
| `.campo-inline` (`.spec select`) | é a linha de especificação **editável**, o átomo da folha; `--controle-alt` viraria a linha numa caixa |
| `.modulo-acesso input` | campo **sobre régua**, não caixa — `border: 0` + `border-bottom` de propósito |
| `.arquivo-acionador input` | input de arquivo escondido, não é superfície visível |

`color-scheme: dark` vive na base do elemento, não em `.dashboard .dash-view`:
é ele que põe o seletor de data e o calendário nativos no tom do produto, e
preso ao painel deixava o resto do produto com o tema do sistema operacional.
