    Conhecimento, feedback e avaliações¶

    Fontes suportadas¶

    O acervo pode receber PDF, DOCX, TXT, Markdown, CSV, JSON, HTML, imagens, texto escrito no painel e URL HTTPS. Documentos viram trechos pesquisáveis. Imagens passam por uma interpretação/OCR no provedor visual configurado; conteúdo visual precisa chegar a esse provedor e não fica só no navegador.

    Cada fonte tem estado de processamento e erro. Uma URL pode ser verificada novamente. Se o conteúdo mudou, a nova cópia entra como rascunho; a cópia publicada continua ativa até a próxima publicação. Para reprocessar um upload que falhou, reenvie o arquivo original — o servidor não guarda o arquivo bruto para retentativa.

    Busca e respostas¶

    Antes da inferência, a API consulta trechos relevantes da base publicada e os adiciona ao prompt com o nome da fonte e a posição do trecho. A resposta pode citar essas referências. O TARS não garante que toda resposta esteja correta; revise documentos, instruções e resultados.

    const conhecimento = await buscarTrechos(instanciaId, texto);
const mensagens = montarPrompt(
  instancia,
  historico,
  texto,
  conhecimento.map((doc) => `[Fonte: ${doc.nome} — trecho ${doc.ordem + 1}]\n${doc.conteudo}`),
);

    Trecho representativo do webhook Telegram. A implementação também registra quais fontes foram usadas para apoiar métricas de operação.

    Ciclo de vida do conteúdo¶

    stateDiagram-v2
  [*] --> Rascunho
  Rascunho --> Processando
  Processando --> Pronto
  Processando --> Erro
  Erro --> Processando: reenvio do arquivo
  Pronto --> Publicado: publicação aprovada
  Publicado --> Rascunho: URL alterada ou remoção solicitada
  Rascunho --> [*]: descartado

    Avaliações de regressão¶

    Cadastre pares de pergunta/resultado esperado. Publicações executam os casos obrigatórios contra o rascunho e bloqueiam a promoção em caso de falha obrigatória. Uma avaliação textual não substitui revisão humana: defina critérios claros e representativos do atendimento real.
